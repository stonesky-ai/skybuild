    Split or merge tasks

    Use exact task IDs and allocation arrays. Preview the plan before applying it. Only proposed tasks with no execution history can be replaced.

    Plan fields and example

    Split: reason, children (2–10 new task definitions), and incoming (each dependent ID mapped to child IDs). Merge: reason, source_task_ids, expected_revisions, one new target definition, and incoming_dependents. Each new task needs title, description, acceptance_criteria, dependencies and any source architecture_refs.
