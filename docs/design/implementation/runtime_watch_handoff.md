# Pilot runtime observation handoff

Task branch: `task/runtime-watch`. Source base: `257216c5498b95d5a6e56bca60c31abcd6736226`. This bounded support change adds read-only observation of the intentional pilot Compose runtime to the existing host watcher. It does not change deployment, queue authority, scheduling, launch permissions or lifecycle policy.

The existing minute loop now records separate `docker_gate` and `docker_runtime` sections. Gate observations retain disposable-container age and leftover semantics. Runtime observations select only the `skybuild-pilot` Compose project, recheck its project label, and inspect only name, lifecycle state, health status, hard memory cap and ownership label. Names are sanitized and bounded; IDs are validated. Environment variables, mounts, credentials and healthcheck output are never retrieved. Two intentional database/API containers may be present while gate leftovers remain zero. A running API with no configured Docker healthcheck is distinguishable from a database with a healthy healthcheck.

Runtime failures produce `attention`; unavailable or invalid observations produce `unknown`, including missing or unlimited memory caps. The aggregate sample propagates those states. Zero runtime containers produce `absent`, not an assertion that an expected deployment is healthy. Desired deployment state remains a separate contract. Commands have five-second timeouts and at most 32 selected containers are inspected. The existing CPU-only loop, lifetime, lock and 8 GiB reserve remain in place.

The deployment session encountered a read-only default Docker configuration directory. Its workaround is a task-owned writable scratch directory supplied through `DOCKER_CONFIG`, with `COMPOSE_BAKE=false`. This is a writable client-configuration path, not a copy of authentication material. Do not copy credentials into that scratch directory or print existing Docker configuration. This task performs no deployment writes, Docker cleanup, service stop/start or watcher restart.

The parent must obtain independent exact-head review, integrate through a frozen bundle with the required combined gate, propagate the accepted script and skill, then replace the current watcher through its owned lifecycle handle. Updating the file on disk does not update a watcher's loaded Python implementation. Existing legacy advisory watchers must not be killed by namespace-relative PID or broad name matching.

Focused validation uses mocked Docker selection and inspection, unavailable and malformed inventory, runtime health and memory-cap failures, name sanitization, ownership changes, and aggregate sample semantics. It starts no container. The parent retains responsibility for combined-gate evidence and any separately authorized live observation.
