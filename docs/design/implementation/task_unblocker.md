# TaskUnblocker

Task `SKYBUILD-BLOCKED-TASK-EVIDENCE-RECHECK` is priority P4. A Python process checks the queue every two hours. It uses no model. Each sweep has a 120-second deadline, five-second HTTP calls, zero transport retries, and an overlap lock. A stable ID cursor must reach a short page before any action. The inventory has a 2,000-task bound. An incomplete inventory fails closed.

The default is GET-only. Diagnosis covers legacy tasks, expired claims, missing current validation, integration acceptance, pending effects, CPU holds and source binding gaps. Findings contain a reason, evidence SHA-256 and actual UTC verification time. Source dates are preserved. Heartbeat timestamps are excluded from the decision hash. A finding is emitted once per changed fingerprint. Cheap API reads still run each sweep because exposure and claims can change without a task definition change. Immutable completed or retired tasks receive no follow-up reads.

An elapsed explicit UTC deferral can be resumed automatically. A milestone, pending action, held claim, reserved CPU, held effect or truncated execution page prevents this action. The task returns to Ready for reassessment; no worker starts. The API rechecks permissions, current inputs, revision and exposure in its transaction. Dependency-completion candidates receive guidance only. Host memory remains a worker admission decision.

Before a POST, the process rereads the exact task, workflow and execution inputs. It creates and fsyncs a private intent and sent marker. It sends once with the exact expected revision and idempotency key. History must prove the exact task, operation, revision and Deferred-to-Ready event. An uncertain result permits GET-only reconciliation, even if a later finding changes. It never replays a POST. Definitive rejected requests remain in the journal.

The source audit records only API-derived task revision, attempt, fence, ref, commit and base. An exact CPU dispatch can add worker, host and assignment digest. Missing repository and worktree fields remain null. The existing task API does not provide a durable typed repository/worktree binding. Follow-up task `SKYBUILD-TASK-SOURCE-BINDINGS` owns a separate append-only database change after accepted migration017 for future launcher bindings. Do not infer a path from a branch or add speculative metadata to active tasks.

## Changed evidence in the task journal

For a Petri task on Hold or Deferred, a changed finding can use the accepted `update_control` event when that event is currently available. This requires complete execution pages, no pending action, no held claim, no reserved CPU and no held effect. The current blocker must have positive factual support: a future explicit UTC deferral, or a stated dependency blocker whose prerequisites still lack accepted completion. Generic free text alone is insufficient. Before the one send, reread the task, workflow, execution and each dependency, then recheck the decision against the actual current UTC clock.

The update preserves the original blocker and next action, and appends a bounded note with observed facts, verification UTC and evidence SHA-256. It keeps Hold or Deferred and does not release a blocker. Original task and observation source times are retained separately in the local finding and remain unchanged in the journal's prior state. This tool's own appended note and control revision do not create a new change fingerprint. Full API rereads still include exact revisions before sending. The same create-only intent, one-send marker and exact committed-history proof apply to both supported events.

A readable current completion or available `release_hold` alone does not prove that an arbitrary blocker has cleared. These cases remain diagnostic. In-progress, Validating and Integrating findings without a supported evidence event carry an explicit `no_api_journal_route` gap and remain in the private report. The current worker mount and network contract does not expose that report to workers. A separate accepted handoff is required for those states; do not mark task acceptance complete from this narrow route.
