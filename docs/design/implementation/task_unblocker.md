# TaskUnblocker

Task `SKYBUILD-BLOCKED-TASK-EVIDENCE-RECHECK` is priority P4. A Python process checks the queue every two hours. It uses no model. Each sweep has a 120-second deadline, five-second HTTP calls, zero transport retries, and an overlap lock. A stable ID cursor must reach a short page before any action. The inventory has a 2,000-task bound. An incomplete inventory fails closed.

The default is GET-only. Diagnosis covers legacy tasks, expired claims, missing current validation, integration acceptance, pending effects, CPU holds and source binding gaps. Findings contain a reason, evidence SHA-256 and actual UTC verification time. Source dates are preserved. Heartbeat timestamps are excluded from the decision hash. A finding is emitted once per changed fingerprint. Cheap API reads still run each sweep because exposure and claims can change without a task definition change. Immutable completed or retired tasks receive no follow-up reads.

Only an elapsed explicit UTC deferral can be resumed automatically. A milestone, pending action, held claim, reserved CPU, held effect or truncated execution page prevents this action. The task returns to Ready for reassessment; no worker starts. The API rechecks permissions, current inputs, revision and exposure in its transaction. Dependency-completion candidates receive guidance only. Host memory remains a worker admission decision.

Before a POST, the process rereads the exact task, workflow and execution inputs. It creates and fsyncs a private intent and sent marker. It sends once with the exact expected revision and idempotency key. History must prove the exact task, operation, revision and Deferred-to-Ready event. An uncertain result permits GET-only reconciliation, even if a later finding changes. It never replays a POST. Definitive rejected requests remain in the journal.

The source audit records only API-derived task revision, attempt, fence, ref, commit and base. An exact CPU dispatch can add worker, host and assignment digest. Missing repository and worktree fields remain null. The existing task API does not provide a durable typed repository/worktree binding. Follow-up task `SKYBUILD-TASK-SOURCE-BINDINGS` owns a separate append-only database change after accepted migration017 for future launcher bindings. Do not infer a path from a branch or add speculative metadata to active tasks.
