# Frozen SkyBuild ledger import rehearsal

This is the implementation contract for a disposable PostgreSQL rehearsal of SKYBUILD-TASK-CUTOVER. It does not switch task authority. `mastertodo.md`, `deferred.md` and `alreadydone.md` remain the live task ledgers. The import receipt deliberately records `authority = markdown`, and Store refuses API task writes for an imported project while that receipt exists.

Every task ID has an explicit dependency array in the JSON contract. Edges name only stable SkyBuild task IDs that are unconditional prerequisites in the present planning record. Phrases such as “controlled execution,” “applicable slice,” “when selected,” “before broad enrollment,” and “later” remain in the raw brief; they are not silently converted into edges. The broad legacy migration is not a machine dependency of the disjoint SkyBuild self-build target. A later owner-reviewed mapping revision must produce a new plan digest.

The task description stores the complete original Markdown section, including status, full brief, deferral reason/revisit trigger, completion result/evidence, architecture reference and any other field. Metadata records source filename and hash, commit, manifest hash, raw-section hash, source order and original status text. Structured title, normalized status, priority order, acceptance text, architecture reference and explicit dependency IDs are projections for API queries. Where source prose has no unambiguous standalone phase, responsible person, assignee or blocker, the importer uses `phase = imported`, `responsible = owner`, `assignee = null`, `blocker = null`, and a manual review next action for unfinished tasks. These defaults do not assert that the ledger named those values. Review and reconcile those fields before any authority switch; the raw section remains the lossless evidence.

## Rehearsal and acceptance boundary

Run `python -m skybuild ledger-import` from the repository root to inspect the full dry-run plan without database access. For an isolated database whose exact configured name starts with `skybuild_import_test`, explicitly run migrations and then use `ledger-import --apply-disposable --expected-import-sha256 <reviewed digest>`. Apply locks all application data tables for its emptiness check and transaction. It refuses an unrelated nonempty destination, changed ledger bytes, changed mapping, or an altered imported destination. Pre-provisioned principals and grants are allowed because they are authentication setup, not task data. Repeating the same import against unchanged rows returns `unchanged` without adding history.

The rehearsal imported 28 tasks: 5 in progress, 9 proposed, 12 deferred and 2 done. The CLI's separate-process replay returned `unchanged`. PostgreSQL tests cover dry-run fidelity, changed source and mapping refusal, unrelated destination refusal, transaction rollback on journal failure, API read/history and write denial, conflicting replay, and Store recreation after import. No live ledger files, authority manifest, deployment or worker process changed. Final cutover still needs an accepted frozen source, explicit authority switch/recovery boundary, API field reconciliation and deployment controls from architecture section 4.

After migration 004 added task lineage, replay verification was tightened to reject unexpected lineage rows, multiple import receipts and changed receipt task/status counts or authority. It locks the lineage table with the other application data tables. Independent `import_review` accepted the correction after checking the Store transaction's receipt-table lock against a concurrent writer. Focused disposable importer tests passed 9 cases; the full suite passed 143 with the existing upstream Starlette warning. This remains a rehearsal verifier, not an authority switch.
