# Structural workbench controls

The launch-free task workbench now exposes the existing guarded split and merge API operations. An owner enters a JSON plan and previews it against the selected task revision before applying. The preview shows split acceptance, architecture-reference and prerequisite coverage, or fetches every merge source to show its revisions and source requirements. It also displays the complete request, including dependent-to-child allocations and target definitions, as inert text. Editing the plan or changing the selected task invalidates Apply. The browser submits the exact parsed plan that was previewed; the API remains the enforcing boundary for mapping completeness, source state, revision checks, journaling and idempotency.

This is a structural planning control for proposed, never-started tasks only. It does not authorize execution or change the Markdown task authority. The independent `structure_ui_review` session found that the first preview hid allocation arrays and merge target/source scope. The correction passed re-review. Browser-handler regression covers exact IDs, the displayed mapping and target fields, invalidation after edit, and revision-bearing submit. The full disposable PostgreSQL suite passed 134 tests with the existing Starlette TestClient deprecation warning.
