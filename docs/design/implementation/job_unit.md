# Bounded local attempt unit

This adapter is a small execution primitive for a future admitted SkyBuild task attempt. It does not decide whether a task may run, call an inference model, restart an attempt, or dispatch from a timer. The controller must first reserve task identity, resources, model usage, and authority under the architecture's admission contract. No live worker launch is enabled by adding this script.

`scripts/skybuild_job_unit.py` adapts the transient systemd user-service pattern from SkyKeep commit `383d3d3` (`scripts/agents/session_keeper.py`, `unit_properties` and `SystemdSpawner`; `scripts/lanes/scoped.sh`, memory cap validation). It uses `systemd-run --user` with `Nice=10`, `MemoryHigh` strictly below `MemoryMax`, `MemorySwapMax=0`, `RuntimeMaxSec` at most eight hours, `NoNewPrivileges=yes`, a declared working directory and input/output files, and an empty environment with a small allowlist. The cap and soft threshold are supplied by separate resource admission. The adapter never uses SkyKeep's permission-bypass launch flags.

One attempt maps to a stable `skybuild-job-<digest>.service` name derived from task and attempt IDs. Before launch, the adapter verifies the user bus and atomically creates a mode-0600 JSON launch intent in a required local state directory. The intent survives a launcher crash. A repeat start, including from another worktree, refuses to launch; a failed or ambiguous `systemd-run` response retains the intent for reconciliation. `RemainAfterExit=yes` keeps normal completion available to `systemctl show`. The observer reads active/result/exit status, `MemoryCurrent`, `MemoryPeak`, and `ControlGroup`, then atomically records the latest sample in the manifest. Completed memory peak remains after unit unload. An unknown unit state remains unknown; a timer must not treat it as permission to retry.

The capacity observer may read up to its bounded manifest inventory. `launch_intent` and `unknown` require reconciliation before new resource admission. `memory_max_bytes` is the hard cap; `memory_current_bytes` is a sampled use value; `memory_peak_bytes` is a best-effort peak from systemd. A missing peak is unknown, not zero. The observer must reserve remaining exposure for active units and maintain the owner's 8 GiB host reserve. Forensic OOM attribution still needs cgroup event counters or supervisor/kernel evidence; an exit code alone does not prove OOM.

Only the exact unit named in a local manifest can be stopped through this adapter. The adapter does not remove manifests, reset failed units, kill processes by name, or clean worktrees. Reconciliation and eventual retirement need a separate fenced lifecycle operation. A rootless user bus must be available to the launcher; the current Jeltz Codex sandbox cannot reach its user bus, so a live systemd check belongs to an authorized host-level process or another qualified box. Tests mock systemd commands and start no real units.
