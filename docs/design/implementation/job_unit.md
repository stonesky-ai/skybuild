# Bounded local attempt unit

This adapter is a small execution primitive for a future admitted SkyBuild task attempt. It does not decide whether a task may run, call an inference model, restart an attempt, or dispatch from a timer. The controller must first reserve task identity, resources, model usage, and authority under the architecture's admission contract. No live worker launch is enabled by adding this script.

`scripts/skybuild_job_unit.py` adapts the transient systemd user-service pattern from SkyKeep commit `383d3d3` (`scripts/agents/session_keeper.py`, `unit_properties` and `SystemdSpawner`; `scripts/lanes/scoped.sh`, memory cap validation). It uses `systemd-run --user` with `Nice=10`, `MemoryHigh` strictly below `MemoryMax`, `MemorySwapMax=0`, `RuntimeMaxSec` at most eight hours, `NoNewPrivileges=yes`, a declared working directory and input/output files, and an empty environment with a small allowlist. The cap and soft threshold are supplied by separate resource admission. The adapter never uses SkyKeep's permission-bypass launch flags.

One attempt maps to a stable `skybuild-job-<digest>.service` name derived from task and attempt IDs. Before launch, the adapter verifies the user bus and atomically creates a mode-0600 JSON launch intent in a required local state directory. The intent includes a random `launch_nonce`, supplied to systemd as the unit Description. The intent survives a launcher crash. A repeat start, including from another worktree, refuses to launch; a failed or ambiguous `systemd-run` response retains the intent for reconciliation. After a successful submission, the adapter requires a loaded unit with the matching Description and a valid nonzero `InvocationID`, then atomically pins that ID in the manifest. A missing unit, missing identity, lost start reply, or interrupted identity persistence requires reconciliation; later observation never adopts an unpinned invocation.

`RemainAfterExit=no`, `KillMode=control-group`, and `TimeoutStopSec=10` cause systemd to stop all remaining child processes when the main process exits. `SendSIGKILL=yes` permits forced termination after the stop timeout. `OOMPolicy=kill` stops the service if an OOM event affects a process in the service. These settings prevent a completed main process from leaving a retained active service with language servers. Before it uses a loaded unit sample, the observer checks the launch nonce and InvocationID from the same response. A mismatch causes an error and preserves the manifest. Legacy manifests without these fields require inspection. Memory peak data can become unavailable after unit unload; missing data stays unknown. A peak saved before unload remains in the manifest. An unknown state does not permit a retry. These checks do not isolate the user bus from another process with the same user ID.

The capacity observer may read up to its bounded manifest inventory. `launch_intent` and `unknown` require reconciliation before new resource admission. `memory_max_bytes` is the hard cap; `memory_current_bytes` is a sampled use value; `memory_peak_bytes` is a best-effort peak from systemd. A missing peak is unknown, not zero. The observer must reserve remaining exposure for active units and maintain the owner's 8 GiB host reserve. Forensic OOM attribution still needs cgroup event counters or supervisor/kernel evidence; an exit code alone does not prove OOM.

`JobUnitManager.stop()` is disabled and raises an explicit error without issuing a systemd command, including for a matching invocation. The inherited SkyKeep stop pattern and `systemctl stop` target a unit name; checking InvocationID immediately beforehand cannot prevent replacement between check and stop. The [systemd D-Bus contract](https://github.com/systemd/systemd/blob/main/man/org.freedesktop.systemd1.xml) exposes `StopUnit(name, mode)` without an expected InvocationID. Random names alone do not establish exclusive lifecycle ownership on the shared user bus. A future stop implementation needs a qualified effect that cannot signal a replacement invocation, or qualified isolation and lifecycle ownership that excludes replacement. Runtime limits remain useful bounds, but this adapter currently supplies no operator/emergency physical-stop mechanism and cannot qualify managed execution by itself.

The adapter does not remove manifests, reset failed units, kill processes by name, or clean worktrees. Reconciliation and eventual retirement need a separate fenced lifecycle operation. A rootless user bus must be available to the launcher; the current Jeltz Codex sandbox cannot reach its user bus, so a live systemd check belongs to an authorized host-level process or another qualified box. Tests mock systemd commands and start no real units.

## Review correction and bounded validation

This remediation belongs to `SKYBUILD-EXECUTION-CONTROLS` and preserves branch `task/job-unit`, original head `d8df1966b883f60caaf21c9607ac1b083eb7c58a`, and its original independent CHANGES REQUESTED review. The required finding concerned stale unit-name manifests attributing or stopping replacement invocations. The correction pins launch identity for observation and removes the unsafe stop effect. It does not claim admission, billing protection, bus isolation, deployment, or live launch/stop qualification.

Offline injected-runner tests cover matching identities, InvocationID replacement/missing values, changed launch nonce, failed starts, interrupted pin persistence, restart recovery, legacy manifests, completion peak retention, and disabled stop. Existing resource/runtime/environment restrictions remain tested.

A bounded TLA+ model checks two invocation generations and three actions: check generation 1, replace it with generation 2, and stop the current named unit after the check. TLC finds the unsafe trace `check(1), replace(2), stop(2)` in four states (six distinct states discovered). With the stop action disabled, TLC exhaustively checks four distinct states without an invariant violation. This establishes only the modeled limitation and disabled effect, not an atomic systemd stop protocol. The unsafe variant is the nonvacuity check; the safe variant deliberately offers no stop liveness. SANY and TLC run offline in `/tmp/skybuild-job-unit-model`; no user-bus calls occur.
