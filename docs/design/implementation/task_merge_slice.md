# Atomic task merge slice

This slice adds `POST /api/v1/projects/{project_id}/tasks/merge` for isolated task development. The caller supplies 2–10 source IDs with their expected revisions, one new target definition, all external incoming dependent IDs and a reason. The target explicitly preserves the union of source acceptance criteria, architecture references and external prerequisites. Internal dependencies among merged sources do not become target self-edges. The target inherits the highest source priority by numeric order. Full source briefs, evidence and task IDs remain in their superseded records and immutable history.

One transaction serializes the project dependency graph, validates all revisions and incoming dependents, creates the target, checks cycles, rewires dependents, journals every affected task and appends source-to-target lineage. Identical replay returns the original result; a stale revision, missing incoming dependent, dropped criterion/reference/prerequisite or cycle rolls back all changes. Until attempt/effect reconciliation exists, both sources and every rewired dependent must be proposed with no execution history. Imported SkyBuild tasks remain write-blocked under Markdown authority.

Separate `merge_review` found that target architecture references were initially omitted. The target contract now accepts them and requires the source union; the same check was added to split children. Distinct-reference preservation and omission rollback tests pass. The independent reviewer accepted the correction. Full structural workflow still needs richer owner preview and workbench controls, safe handling of active tasks/effects, guarded completion and evidence-based phase transitions. This slice does not authorize execution or cutover.
