## Independent review correction

The coordinator's independent exact-head review of `e37f894` found an identity-publication race: the worker could truncate its PID record outside the controller lock after the parent released that lock. Another checkout could observe the partial record and start a duplicate. The coordinator reproduced that interleaving in a bounded TLA+ model. This revision moves the shared control lock into the state module and makes worker publication and identity cleanup acquire the same lock already held by controller mutations. The parent still detects its own worker through `/proc`, publishes its record, and releases the lock before the worker acquires it, avoiding a startup deadlock. A deterministic two-thread regression pauses worker publication with an empty record and proves another-checkout start waits, then recognizes the published worker without spawning.

The reviewer also identified a timeout path that removed identity after termination had not been acknowledged. A startup-exposure record now pins PID and kernel start time before waiting for worker visibility. An unresolved timeout retains that record and blocks later starts across checkouts until physical process exit or changed kernel identity is verified. The regression reaches the visibility timeout and termination timeout, checks retained exposure, and proves a retry is refused. The updated targeted suite passes 29 tests. No live process controls were exercised.


## Successor correction for post-spawn record failure

Independent review of frozen candidate `aec7132` identified another reproducible path: Popen succeeds, then the startup-record write fails before creating a file. A deterministic regression with a fake live child and simulated ENOSPC reproduced two launches on two retries. Frozen candidate and branch remain unchanged; this correction is on successor branch `task/review-marshalls-start-intent-20261009`.

The controller now writes and fsyncs a separate launch-intent file and its directory before Popen. An absent process record with retained intent means unknown exposure and blocks retry. Partial or malformed process records also fail closed without clearing intent. Intent is cleared after acknowledged startup, confirmed process exit, or Popen's known failed-exec OSError path, which reaps the failed child before raising. Any unknown post-spawn recording failure retains intent. A missing process identity requires manual reconciliation; the code does not infer that the worker stopped. Tests prove one launch across post-spawn recording failure/retry, no launch after intent durability failure, safe cleanup after known Popen failure, and retained intent after a partial process record. Updated targeted validation passes 35 tests, with the existing Starlette warning. No live worker was launched.

Worker PID publication now writes and fsyncs a private pending file, atomically replaces the prior record while holding the shared lock, and fsyncs the directory. An ENOSPC during pending publication therefore preserves the prior valid identity. Malformed or unreadable process identity fails closed rather than falling back to checkout-local discovery. Additional regressions cover partial worker publication and a malformed PID record.
