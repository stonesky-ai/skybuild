# Dependency readiness and durable invalidation

This slice follows architecture A33 sections 4–5 and the task workflow's immutable history contract. Markdown remains the live SkyBuild task authority. It adds no worker admission, service launch or authority switch.

Readiness evaluation runs synchronously under the existing project graph lock. A separate PostgreSQL readiness record retains input and assessed generations without changing frozen importer task snapshots. Every accepted task mutation invalidates its transitive dependents in the same transaction, journals the invalidation, and revokes stale readiness. Deferred and superseded dispositions remain intact; previously started work remains held for effect reconciliation.

A guarded `ready` action requires explicit acceptance, no started history, and current completed prerequisites. It acknowledges only the generation evaluated while holding the graph lock. A later input change leaves a newer dirty generation. Manual readiness remains separate from execution authority.

The input contract is architecture SHA-256 `dccd30d1c1bc0d6c0b951c6ede9f1e1db5565e4dd7aac40e3082339` and workflow SHA-256 `fedc22b2fc7777879d15c3bc156166b29094ef118dd933c72a0f17292acbada6`, from base commit `9902744`. Migration 005 creates the readiness projection. Accepted task replacements increment input generation; ready acknowledges its evaluated generation, while the future `completed` operation acknowledges existing inputs. Journal snapshots expose these values in reserved workflow metadata. Creation leaves an unassessed record; imported task snapshots remain unchanged.

Invalidation traverses dependency and milestone edges once per mutation, preserves deferred triggers, and retains superseded records. Reopened or edited prerequisites block their transitive dependents. Every dirty transition increments revision, so stale edits and retries cannot clear newer invalidations. Merge source retirement rereads earlier invalidated source state to retain contiguous journal snapshots.

The standalone candidate passed the full disposable PostgreSQL suite: 150 tests, with one existing Starlette deprecation warning. Two subsequent focused regressions also passed; all six dependency readiness regressions pass. Cases cover current prerequisite readiness, reopened completion, transitive invalidation, edge edits, milestone deferral, an input change during evaluation, idempotent replay, unassessed done labels, and internal merge edges. No live database or service changed. Independent adversarial review is pending.

This slice does not define accepted completion evidence. Before integration with the completion slice, both dependency checks must require its `current_completion()` predicate as well as readiness generation freshness. No started task may use the early ready action; effect reconciliation remains a later requirement. Evaluation is synchronous under the project graph lock; no background evaluator, scheduler or model wakeup is introduced.

Independent review found that reverse-order rewiring could leave structural responses and idempotency receipts at intermediate revisions. Split and merge now reread every returned task after all mutations; both regression cases compare initial responses and retries with committed projections and final journal snapshots. The corrected full disposable PostgreSQL suite passed 154 tests with the existing Starlette warning. Re-review is pending.
