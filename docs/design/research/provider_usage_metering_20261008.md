# Provider usage metering evidence

Checked 2026-10-08 for planning only. No authenticated provider/account requests, CLI sessions, inference calls or installs were performed. Public documentation and static strings in the installed Codex binary establish possible interfaces, not working account integration or pricing guarantees.

## Verified surfaces and limits

- **Codex:** official OpenAI documentation describes `account/rateLimits/read` and `account/rateLimits/updated`, with percentage, window and reset information, including multiple quota buckets. It separately documents `account/usage/read` for token-activity summaries. These are metadata operations; token activity is not itself a conversion into subscription quota. The installed `/usr/lib/chatgpt/resources/codex` binary contains the rate-limit method and field names, but no authenticated operation was tested. [Codex App Server](https://learn.chatgpt.com/docs/app-server).
- **Claude Code:** `/usage` displays plan usage limits and rate-limit status; `/cost` displays session usage/spend. This establishes a client-visible meter, not a stable personal-subscription REST or headless interface. [Claude Code cheatsheet](https://support.claude.com/en/articles/14553413-claude-code-cheatsheet).
- **Anthropic API:** the published Usage & Cost Admin API reports organization API data and is unavailable to individual accounts. Do not substitute that data for a personal Claude subscription percentage. Account-specific access and the correct metering surface need qualification. [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api).
- **xAI API:** the Management API documents historical team API usage. This does not establish the owner's Grok subscription balance, model-specific quota or an expiring-token inventory. Those capabilities remain unknown. [Billing Management](https://docs.x.ai/developers/rest-api-reference/management/billing).
- **CLI resume behavior:** Claude Code documents automatic continuation after usage-limit reset in some interactive sessions. This can resume work after a wrapper's original decision; an execution adapter must enforce the current approval/budget contract at supported boundaries rather than assuming a long-running process stays authorized forever. No local setting or running session was changed. [Interactive mode](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset).

## Billing and design consequence

The reviewed pages do not establish a universal guarantee that every provider usage query is free. A metadata operation is different from generating a model answer, but its provider-specific fees and request limits still need verification. Record query billing as unknown until established; do not run paid experiments to guess. SkyBuild's own cached REST reads will not invoke an LLM or provider query.

Use one collector, passive metadata where available and bounded/coalesced status refresh. Return source, coverage, observed time, age and native window/pool/model identity; unknown values remain null. Model-level counters must not clone a shared pool into independent balances. Neither local token estimates nor changes in account-wide percentages prove attributed build consumption, complete coverage of other tools or exact quota ceilings. Keep model/pool expiry and reset semantics distinct, with provenance. Qualification should identify supported authentication, granularity, attribution, polling cost, freshness, cancellation and unattended resume behavior before autonomous adoption.

## Remote authentication and credential lifetimes

Public documentation was checked without opening local credential files, generating tokens or signing in anywhere.

- **Codex:** prefer `codex login --device-auth` on a supported remote runner, completing the browser approval locally. OpenAI also documents copying the local auth cache to a trusted headless machine as a fallback. ChatGPT sign-in refreshes tokens automatically during use. The reviewed page does not give a universal fixed token lifetime, so do not hardcode one. Isolated profiles and coordinated persistence/refresh need adapter qualification. [Authentication](https://learn.chatgpt.com/docs/auth).
- **Claude Code:** `claude setup-token` generates a one-year OAuth token for subscription-backed CI/scripts. It prints the token without storing it; remote injection uses the documented OAuth-token environment setting. The token permits model requests, not every interactive feature, so do not assume it can fetch account usage. Regular login/profile refresh and static API keys are separate paths; credential precedence can select a different billing mode than intended. Verify the selected account and mode per runner. [Authentication](https://code.claude.com/docs/en/authentication).
- **xAI API:** API-key metadata includes `expireTime`; a configured past expiration causes rejection. Inspect the selected credential's lifecycle rather than inventing a fixed duration. This is API-key documentation, not proof of a portable consumer Grok login token. [Accounts and Authorization](https://docs.x.ai/developers/rest-api-reference/management/auth).
- **Grok consumer quota:** current official help describes a weekly pool shared across products and a usage/reset display. This supports preserving native shared-pool semantics; it does not establish automated account access, a particular user's balance or credential lifetime. [Grok FAQ](https://docs.x.ai/grok/faq).

Keep token material in protected per-account profiles/secret storage. Initial planning favors supported runner login or documented enrollment/transfer over a new credential broker. Registry/REST data holds references and non-secret expiry/refresh state. Account rotation and credential refresh never replenish daily/interval budgets or extend build approval. No remote provisioning or token transfer occurred.

## Subscription billing boundary

The owner requires ordinary existing subscription costs and rejects API/usage-credit rates. Treat supported subscription authentication and prevention of paid continuation as separate qualification questions.

- **Codex:** OpenAI distinguishes ChatGPT subscription sign-in from API-key access billed at API rates. It documents restricting login to ChatGPT authentication. That restriction is useful evidence for adapter design, not proof that every plan, model/tier or overage setting is suitable. [Official OpenAI authentication documentation](https://learn.chatgpt.com/docs/auth).
- **Claude Code credential precedence:** subscription sign-in and Console/API billing are separate. An API key can override subscription authentication; current headless credential precedence must be qualified for the installed version. The plan guidance recommends subscription-only credentials and declining API-credit continuation. [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan), [Authentication](https://code.claude.com/docs/en/authentication).
- **Claude paid continuation:** paid plans can use separately charged usage credits after included limits. Enabled credits continue requests at standard API rates; turning off automatic reload alone does not prevent spending an existing balance. A subscription login therefore cannot by itself establish the owner's billing restriction. [Manage usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans).
- **Grok:** the reviewed consumer quota and API-key pages do not establish a supported autonomous subscription-only coding path with enforceable zero-overage protection. Keep that adapter unqualified rather than treating an xAI API key as a substitute subscription credential.

Proposed adoption requires verified account/auth/billing identity, approved model/tier, isolated runner environments and a supported way to prevent paid continuation. Unknown protection parks autonomous inference. Do not use a paid inference call to discover which billing mode was selected, purchase credits or change account settings during planning. Meter polling also requires known acceptable billing; passive evidence and SkyBuild's own cache remain available without an upstream query. No authenticated billing check or end-to-end protection test has been performed.
